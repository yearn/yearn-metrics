Outcome and boundaries

A pricing change should have one explicit owner for provider selection, one clear result from acquisition, and a deliberate rule for retrying or replacing stored evidence. Adding a provider for earnings must not silently change fee or TVL valuation.

Preserve the current earnings default of Yearn Prices with configurable fallback, the explicit Yearn-only mode, exact end-of-day validation, genuine-zero versus unknown values, offline analysis, and the existing CLI/export contracts. Canonical fee USD valuation introduced later is a separate product from legacy vault-fees.

The plan does not change economic formulas, choose a new default provider, consolidate the earnings/fee/TVL tables, rescan history, or republish datasets. Removing fallback may simplify the product, but that is a separate behavior decision requiring evidence of the resulting coverage change.

1. Job policyAllowed providers, time convention, fallback permission, and retry choices.
2. Provider clientsTransport and evidence validation; return a quote or an explicit failure.
3. Job storageSelect work, persist evidence, preserve usable quotes, and schedule retries.
4. ValuationRead eligible evidence, calculate USD values, and report completeness.

This is the target separation. Only the small earnings-policy consolidation belongs in #24; the provider/result extraction belongs in the separate issue below. Job-specific caches and accounting remain separate.

Extract price-provider clients and explicit result contracts

Problem. pricing.py combines HTTP clients, evidence parsing, local onchain calculations, batch orchestration, retry selection, and database writes. Fee valuation calls private helpers from this module; TVL imports its fetch functions. These dependencies make local changes affect unrelated job policies.

Scope. Extract the Yearn and DefiLlama client code behind small public functions. Give each target result explicit value, status/reason, provider, requested time, evidence time, and provenance fields. Distinguish a failed batch request from individual unresolved targets. Keep authentication/configuration failures distinguishable from unavailable price evidence.

Keep work selection, cache writes, and policy decisions in the earnings, fee, and TVL consumers. Give local onchain adapters a separate module boundary and an explicit dependency on the quotes they use. Replace cross-module private-client imports with the public interface. Use concrete functions and result types; no plugin registry or generic provider framework is needed.

Acceptance. Provider clients perform no SQL or valuation. Existing callers and CLI behavior remain supported. Job-specific cache identities, fallback permissions, retry rules, and export meanings remain intact. Tests cover mixed valid/invalid targets, typed fatal errors, provider/time provenance, and the lifecycle regressions retained from #24. Integration tests cover earnings, canonical fee USD, and TVL with their different policies.

Replacement rule. Shared result terminology must distinguish an unsuccessful fetch from explicit evidence rejection. Consumers decide whether a prior quote remains eligible; #35’s deliberate quote withdrawal must remain possible.

Out of scope. A unified cache/schema migration, new providers, changed default source policy, new pricing formulas, historical backfills, and publication changes. Do not silently standardize all batch-failure retry behavior during extraction; preserve or explicitly review each consumer’s request budget.

Dependencies and delivery. Reconcile #24’s fixes through #27, #28, and #30 first. Implement against a base containing all affected callers, in small behavior-preserving commits. If PostgreSQL is present on that base, include its persistence integration checks. Review any proposed behavioral change separately from file extraction.
